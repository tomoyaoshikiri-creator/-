# 集金設定の柔軟化 — 段階導入設計（仕込み）

## 現状（2026-11-02にコード確認）
- 集金項目は月額ベース（`flat_monthly_amount`、学年帯・選手別の`monthly_amount`）。
- 集金周期は1/2/3/6/12か月。年度は4月〜翌3月。
- 選手別に免除・金額上書き・開始日・停止日を設定できる。
- 現行`isPlayerBillableForPeriod`は請求期間と在籍期間が1日でも重なると請求対象とする。12か月周期で7月加入でも4〜3月の期間に重なるため、満額請求になりうる。
- 既存請求の作成・入金管理・会計計上は既存ロジックのまま保持する。

## 設計方針
1. **金額単位**: 月額 / 年額。集金周期と独立。
2. **集金周期**: 毎月 / 2か月 / 3か月 / 6か月 / 年1回。
3. **途中加入月の扱い**: 加入月から / 翌月から（費目単位の初期値、選手単位の例外）。
4. **年額費目の途中加入**: 満額 / 月割り（費目単位の初期値、選手単位の例外）。
5. **選手別例外**: 免除、開始・停止日、基準額の上書き、整数円の年度調整。
6. **年度の総額**と**請求タイミング**は分離し、期間別請求の合計が年度負担額と一致する。
7. 日割りはこの段階で自動実装しない。必要な場合は個別調整。家庭単位の請求では、選手ごとの計算後に既存の家庭集約ルールを適用する。

## 本PRの範囲
- **純粋なプレビュー計算関数** `src/lib/duesPricing.ts` とユニットテストのみ。
- 既存DB・既存UI・請求生成・入金データは変更しない。
- 現行の請求額に影響しないため、DBマイグレーション前でもマージ可能。
