B-9で対応した項目(モーダルのARIA属性・フォーカス管理・Escキー対応、選手一覧行のキーボード操作、ヘッダー検索欄のラベル・フォーカス表示)とは別に、調査の過程で見つかったが今回は対応を見送った項目。理由は「1PRで安全に直すには影響範囲が大きすぎる」「programmatic な検証手段がなく目視確認が必要」のいずれか。

## フォームラベルの未紐付け(一部対応・継続中)

`src/components/ui/SegButton.tsx`の`FieldLabel`コンポーネントは、現状ただのスタイル付き`<div>`で、`<label for="...">`のように対応する入力欄とプログラム的に紐付いていない。アプリ全体のフォーム(設定画面・各種登録モーダル等)がこのパターンを使っているため、スクリーンリーダーで「この入力欄は何の項目か」が読み上げられない。

`FieldLabel`は後方互換なAPI(`htmlFor`省略時は現状通り`<div>`のまま)として既に対応済みで、呼び出し側を1つずつ`id`/`htmlFor`のペアで結び直す移行を進めている。1つのFieldLabelに複数input(氏/名、時刻の時/分等)が続く箇所や、SegButton/Switch等の非ネイティブ入力・ボタン群の見出しは、対象外として`<div>`のまま残す(`<label for>`で紐付けられる対応が1対1の単一inputの場所のみ移行する)。

移行済み(呼び出し側のid/htmlForペアリング):
`ForgotPasswordForm` / `SignupForm` / `ResetPasswordForm` / `LoginForm` / `InviteForm` / `karte/team/attendance-report` / `settings/audit-log` / `NewTeamForm`(チーム作成) / `NewPlayerModal`(選手登録) / `NewScheduleModal`(予定登録) / `NewNoticeModal`(お知らせ、タイトル・本文のみ) / `settings/name` / `settings/password`

未対応(呼び出し元の数が多く、影響範囲確認のため順次対応): 上記以外の約45ファイル(会計・コーチ日報・ライブラリ・検定管理・ワークアウト等の各種登録/編集モーダル)。

## 色コントラストの監査(対応済み)

主要なtext color token(`--orange`/`--danger`/`--green`、文字として使っている箇所のみ。背景・枠線としての使用はWCAGの非テキストコントラスト基準〈3:1〉で現状問題ないため対象外)を計算で検証したところ、白背景・ページ背景に対する通常文字のコントラストがWCAG AA基準(4.5:1)をわずかに下回る箇所が見つかった。

- `--orange`(デフォルト値、リンク・選択中タブ等の文字): 白背景で4.08:1
- `--danger`(エラー文字): 白背景で3.91:1
- `--green`(勝敗数・入金額等の文字): 白背景で3.30:1

対応として、元の色味を保ったまま白背景で基準を満たす濃さまで暗くした専用token(`--orange-text`/`--danger-text`/`--green-text`、`text-orange-text`等のクラスで利用)を追加し、文字として使われている全箇所(213箇所)を置き換えた。`--orange-text`はチームカラー(`teams.theme_primary`)に応じて`darkenForTextContrast()`(`src/lib/theme.ts`)が自動算出するため、チームが明るい色を設定した場合も追従する(`--danger-text`/`--green-text`はチームカスタマイズ対象外のため固定値)。

ヘッダー上部のチーム名表示(チームカラーのグラデーション上に白文字)は、グラデーションの明るい側(水色寄り)で実測約3.2:1(非テキストコントラスト基準の3:1はクリア、通常文字の4.5:1は未達)。アイコン的な短い文字列での使用のため今回は対応を見送ったが、文字が長くなる用途に転用する場合は再検証が必要。
