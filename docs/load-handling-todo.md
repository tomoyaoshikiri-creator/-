# 負荷対策: 既知の課題(未対応)

B-10で対応したのはDB層のインデックス欠落(`daily_reports`/`game_matches`/`game_player_stat_lines`、`supabase/migrations/0146_missing_load_indexes.sql`)のみ。調査の過程で見つけた、より影響範囲の大きい課題は未対応のまま記録する。

## 一覧画面のページングなし(未対応・影響大)

以下の一覧画面は`.limit()`を指定せず全件取得している。現状のチーム規模(選手数十人・日報/お知らせが数百件程度)では問題にならないが、チームの活動年数が長くなる・チーム数が増える(B-5で自己登録が可能になった)につれて、1画面あたりの取得件数が際限なく伸びていく:

- `/notice`(お知らせ一覧)
- `/report`(チーム日報一覧)
- `/coach-note`(コーチ日報一覧)
- `/library`(ライブラリ一覧)
- `/schedule/history`(予定の履歴)
- `/game/results`(試合結果一覧)
- `/players`(選手一覧)

対応するには「ページング(無限スクロールまたはページ送り)をUIに追加する」というUI変更を伴うため、1PRで安全に検証しきれず今回は見送った。優先度が高い画面(データが増えやすいお知らせ・チーム日報あたり)から、UI変更として別途1画面ずつPRを切るのが現実的。

## 実際の負荷試験(未実施)

大量選手登録チーム・大量同時アクセスを想定した負荷試験(k6等のツールを使った実測)は未実施。今回のインデックス追加も「RLSのteam_idフィルタ・アプリのmatch_id検索がフルスキャンになっていた」というクエリパターンの静的な読み取りに基づく判断で、実測による検証は行っていない。
