# 年間集金方式: DB拡張と段階移行

## この変更
- `accounting_dues_items` に新方式の列を追加する。
- `schedule_mode='legacy'` が既定値。既存の行は旧方式のまま。
- `annual` は `amount_per_collection`, `annual_count`, `collection_months`, `join_leave_rule` が必須。
- DB側で金額、回数、月の範囲、個数、ルール値をチェックする。
- 月の重複は現時点ではアプリ側の検証で防ぐ。DB制約追加を検討。
- 既存の `cycle_months`、`flat_monthly_amount`、学年帯・個別金額は削除・更新しない。
- 請求履歴、請求期間、入金履歴には触れない。

## 本番導入前に必要
1. Supabaseの生成型 `database.types.ts` を新カラムに合わせて更新。
2. 新方式の設定画面・学年帯／個別料金・家庭単位の金額設計を統合。
3. **重要:** 既存の請求生成コードは `schedule_mode` を参照しないため、annualモードの項目が有効化される前に必ず新旧分岐を実装する。設定UIはそれまでannual保存を禁止する。
4. 選手加入後の未確定追加請求、管理者の確認・確定、重複防止、退団時の差額処理を実装。
5. PR #236（計算基盤）とPR #235（集金管理）との整合を確認。
6. 実DBでマイグレーションの適用・ロールバック方針・既存データの動作を確認。

## 注意
このPRは列を追加するだけ。**新方式を使えるようにはならない。**
